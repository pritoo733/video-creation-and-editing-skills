# Creating Instructional Videos

Create a source-grounded, understandable walkthrough with a usable final video and reproducible project files. Read [the production workflow](references/production-workflow.md) for the detailed scene, voice, capture, and assembly method. Read [the app-capture guide](references/app-capture.md) when the tutorial uses a live or demo application.

## Required production record

Maintain these project artifacts as they become available:

1. A brief describing audience, purpose, role(s), viewer outcome, target duration and format, voice, brand, and call to action.
2. An evidence-backed script and scene plan with capture references, narration, on-screen text, and transitions.
3. A capture checklist and a record of unresolved product behavior, claims, privacy concerns, and permissions.
4. A scene manifest or timeline that maps each scene to its source asset, narration, caption timings, and output interval.
5. The editable source project, final video, caption sidecar when useful, and a review record.

## Working rules

- Separate observed app behavior from help text, owner-provided claims, and inference. Flag conflicts for review; do not narrate an unresolved behavior as fact.
- Capture the ordinary intended user experience. Use the role and permissions appropriate to each chapter; identify staff-only material clearly.
- Use sample data approved for filming. Keep credentials, personal identifiers, real account data, and private documents out of recordings and project assets.
- Prefer local, no-cost tools when they meet the brief. Confirm model, music, font, stock, and provider rights for the intended use. A voice that sounds good still needs usage rights.
- Never treat permission to create a video as permission to publish, send, or upload it.
- Do not call a render complete until the final export has been reviewed using the editing skill's review checklist.

## Typical deliverables

Deliver the MP4 plus the script/transcript, captions, scene manifest, and review notes when requested or useful. Keep temporary renders and source assets in a separate project directory. State the actual review method and any unavailable checks.
