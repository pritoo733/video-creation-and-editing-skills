# Worked Example: Four-Scene Product Explainer

This fictional example shows how the repository's brief, research, scene-planning, and review practices connect. “Northstar” and its task-board interface are invented for illustration; none of the product details are real claims.

## 1. Brief

- **Purpose:** Help first-time viewers understand a simple task board.
- **Audience:** People who have never used the fictional Northstar app.
- **Viewer outcome:** Create a task, set a due date, and find it again.
- **Destination and format:** Help center; 16:9 landscape, 1080p, captions on, about 90 seconds.
- **Tone and look:** Calm, direct screen demonstration with restrained labels and cursor emphasis.
- **Call to action:** Try the same three steps in your own workspace.
- **Evidence/rights:** Use an approved demo workspace with fictional sample data; mask account details. Product behavior comes from the supplied demo, not invented narration.

## 2. Evidence and script

The screen recording is the source of truth. Before recording, verify each action in the demo and note the starting state. There are no external factual claims to research in this example.

| Scene | Spoken copy | On-screen evidence |
| --- | --- | --- |
| 1. Promise (0:00–0:12) | “In about a minute, you’ll create a task, give it a due date, and find it again.” | Clean board view; highlight the task list. |
| 2. Create (0:12–0:35) | “Choose Add task. Give it a clear name, then save. You should now see it in your list.” | Perform the action; pause on the saved task. |
| 3. Set a date (0:35–0:58) | “Open the task’s date control, choose a date, and save. Check the date shown on the task before moving on.” | Open the actual date control; select and confirm a demo date. |
| 4. Find and recap (0:58–1:25) | “Return to the list and locate the task you just made. You’ve now created it, set its date, and confirmed where to find it.” | Show the saved task and date together; end on the board with the next step. |

## 3. Scene and capture plan

Record each scene from a clean starting state in the approved demo workspace. Capture at the intended delivery resolution. Move the pointer deliberately, keep each click visible, and hold the resulting state long enough to read. Capture a clean board state for the opening and ending. Do not expose real names, email addresses, notifications, or account details.

| ID | Input/state | Edit notes | Check before approval |
| --- | --- | --- | --- |
| S01 | Clean board opening | Establish the task list and promise | Correct workspace; no private data |
| S02 | Add task form and saved state | Keep entry and save action continuous | Task name legible; saved state visible |
| S03 | Date control and selected date | Show selection and confirmation | Date matches the displayed result |
| S04 | Returned list with task and date | Hold, recap, then settle on end frame | Both task and date visible; CTA accurate |

## 4. Final review record

| Requirement | Where | Evidence/check | Result |
| --- | --- | --- | --- |
| Explain the viewer promise | S01 | Compare narration with brief | Pass / revise |
| Show task creation and saved result | S02 | Watch the rendered scene | Pass / revise |
| Show setting and confirming a due date | S03 | Compare action to visible saved date | Pass / revise |
| Show where to find the task and finish with next step | S04 | Review ending and CTA | Pass / revise |
| Keep demo data private and text readable | All scenes | Inspect at phone-sized playback | Pass / revise |
| Captions match final speech | All scenes | Compare captions to final audio | Pass / revise |
| Export matches delivery profile | Final file | Probe metadata and decode; play through | Pass / revise |
